# KontorKaffe 3.1 – local card archive
The administrator chooses the existing valid A4 PDF once per device/browser profile. Android uses AndroidKeyStore AES-256-GCM and a private no-backup file; browser uses WebCrypto with a nonextractable key in the local IndexedDB profile. Browser encryption is not protection against someone who controls the browser profile/origin; use private devices only. No PDF or plaintext QR tokens are transmitted, committed, or added to the server. Both bind the copy to an opaque admin-only card-set revision and check it before reprinting. The revision detects later membership-card changes; it does not authenticate the contents of the selected PDF. The user must choose the correct original or updated card sheet. Android validates one portrait A4 page; the browser checks PDF signature and size. Local archive can be removed, or lost on uninstall/clearing browser data; keep the original securely. Physical printing and Android Keystore runtime require actual device testing. No new Firebase service or costs.
