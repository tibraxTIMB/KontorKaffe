# KontorKaffe 3.2
The active private QR card is the customer credential, without browser approval. No persistent browser identifier is created by the new client; a random ephemeral value maintains compatibility with the existing Edge API. The customer enters a nickname (1–30 characters) on each order, not a member profile. The server validates supplied nicknames, attaches them to the order, and displays them to the barista. Legacy clients without the field use the member name as a fallback during rollout. Nicknames follow the existing order deletion policy. No QR keys or credits were replaced. Anyone possessing a copy of a valid QR code can order; keep cards private and block lost cards.
